# 三端小程序发布前置清单（2026-10-22）

> 适用：**store / supplier / user** 三端原生微信小程序（admin 仍为 uni-app H5，不在此清单）。
> 现状：三端当前统一使用测试号 `wx4942e19ae41bc1b4`。正式发布前必须**逐端**替换为各自真实 AppID，且**三端禁止共用**（共用会让三端读写同一份微信侧本地存储，演示数据互相串端）。

## 一、前置条件

- 每端一个可用的真实小程序 AppID（`wx` + 16 位十六进制）。
- 可测试真机（微信客户端）与扫码预览权限。
- 网关域名（`VITE_TENCENT_MAP_GATEWAY` 指向）已完成备案并可配置 request 合法域名。
- 腾讯地图 Key / Secret 走服务端环境变量，不进入前端产物。

## 二、逐端替换与预览（store / supplier / user 各执行一遍）

```bash
# 1) 写入真实 AppID（只改 apps/<app>/src/project.config.json 的 appid 字段）
pnpm mp:appid <app> wx1234567890abcdef --dry-run   # 先确认，不写盘
pnpm mp:appid <app> wx1234567890abcdef

# 2) 重新构建（构建整体替换产物；若开发者工具正打开该项目会直接失败，需先关闭）
pnpm build:<app>

# 3) 注册/打开项目并生成真机预览二维码
& "C:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat" open --project apps/<app>/dist/build/mp-weixin
& "C:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat" preview --project apps/<app>/dist/build/mp-weixin --qr-format image --qr-output artifacts/mp-regression/<app>-release-qr.jpg
```

- 完成一端再切下一端，避免三端共用同一 AppID 造成串端。
- 开发者工具 CLI 的 `--qr-output` 实际写出 JPEG 字节，文件名统一用 `.jpg`。
- 替换 AppID 后必须重新构建，产物里的 `project.config.json` 才会同步。
- AppID 只写在源码 `project.config.json`；不要把开发者工具在 `apps/<app>/` 下生成的本地配置提交入库（已 gitignore）。

## 三、微信后台配置

- **request 合法域名**：加入网关域名（腾讯地图反代 `/api/tencent-map/*`）。
- 开发阶段可在开发者工具临时关闭域名校验，但**上传体验版/正式版前必须配置合法域名**，否则真机请求全部被拦。
- 网关部署与 Nginx 反代见 [docs/tencent-map.md](../tencent-map.md)。

## 六、自动化边界（当前口径）

- `pnpm e2e:mp --app <app> --chain <L1|L3|L2>` 依赖本机微信开发者工具与 automator：
  - `store`：页面可渲染（319 view 节点 / 22KB 截图），但 automator `$vm` 缺失 → `BLOCKED`。
  - `supplier` / `user`：view 层未挂载（0 节点 / 约 2.5KB 空白截图）→ `BLOCKED`。
- 结论：本机为环境级故障（详见验收清单第八节），**不得据此宣称链路通过**。发布验收以本清单的人工逐页为准；换到干净环境后再复跑三条链路。
