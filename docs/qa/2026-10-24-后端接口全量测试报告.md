## 二、关键问题

### P1

1. **网关允许 Refresh Token 作为 Access Token 访问受保护接口**
   - 证据：`JwtAuthFilterAuditTest.refreshTokenCannotBeUsedAsAccessToken` 失败，下游 filter chain 被调用。
   - 根因：`JwtAuthFilter` 校验签名和有效期，但未检查 `tokenType == "access"`。
   - 影响：刷新令牌可进入下游请求链路，扩大令牌误用面。

2. **创建订单缺失 `Idempotency-Key` 返回 HTTP 500**
   - 证据：`POST /api/v1/orders` 实测 `500 INTERNAL_ERROR`，期望 `400 BAD_REQUEST`。
   - 根因：必填请求头缺失异常被全局兜底处理为内部错误。

### P2

3. **业务异常未映射对应 HTTP 状态**
   - 影响接口：登录、刷新、商品取价、库存、支付回调、履约、提现审批等。
   - 现象：多数 `BusinessException` 返回 HTTP 200，仅 envelope 中带 `UNAUTHORIZED`、`BAD_REQUEST`、`NOT_FOUND`、`CONFLICT` 等错误码。
   - 根因：`GlobalExceptionHandler.handleBusiness()` 没有设置响应状态。

4. **库存接口未真正使用 `Idempotency-Key`**
   - 缺失幂等键仍可创建预占。
   - 相同幂等键提交不同订单时生成了第 2 条预占，库存从 8 变为 7。
   - 期望：缺失键 400；同键不同请求 409 `IDEMPOTENCY_CONFLICT`，且数据不变化。

5. **订单幂等键未校验请求内容**
   - 相同 key、不同载荷仍返回第一笔订单 HTTP 200，而不是 409 `IDEMPOTENCY_CONFLICT`。

6. **部分查询接口用 HTTP 200 返回空数据**
   - `GET /orders/{id}` 不存在时返回 `200 OK`、`data: null`。
   - `GET /payments/orders/{orderId}` 不存在时返回 `200 OK`、`data: null`。
   - 期望返回 404 `NOT_FOUND`。

7. **刷新令牌重放语义与状态码不符合约定**
   - 旧 refresh token 重放返回 HTTP 200，期望 409。
   - 退出后继续 refresh、非法 refresh、缺失 refresh 均返回 HTTP 200，期望 401/400。

8. **未知路由被全局异常处理为 500**
   - 请求 `/api/v1/org/not-a-real-resource` 返回 500 `INTERNAL_ERROR`，期望 404 `NOT_FOUND`。

### P3

9. **OpenAPI 与实际路由不一致**
   - 缺失的操作：
     - `POST /auth/logout`
     - `GET /org/suppliers`
     - `GET /org/farms`
     - `GET /org/drivers`
     - `GET /org/leaders`
     - `GET /inventory/skus/{skuId}/available`
     - `GET /payments/orders/{orderId}`
     - `POST /fulfillment/orders`
     - `GET /notifications/health`
   - OpenAPI 错误响应和统一 envelope schema 也不完整。

## 七、修复结果（2026-10-27）

- `GlobalExceptionHandler`：为 `BusinessException` 增加 HTTP 状态映射（400/401/403/404/409/429），未知路由 404。
- `JwtAuthFilter`：校验 `tokenType == "access"`，Refresh Token 不再转发。
- `InventoryService.reserve`：新增 `sys_idempotency_record` V2 迁移，真正使用 `IdempotencyService`；缺失 key 400、同 key 同载荷重放返回原预占、同 key 异载荷 409 且不重复扣库存/写流水。
- `OrderService.create`：复用 `request_hash`，同 key 异载荷 409；`GET /orders/{id}` 不存在返回 404。
- `PaymentController.byOrder`：不存在返回 404。
- `AuthService.refresh/logout`：会话区分 `ROTATED`/`LOGOUT` 撤销原因；重放返回 409，退出后刷新/无效/过期返回 401，缺失返回 400。
- `docs/backend/openapi.yaml`：补齐 9 个缺失操作与统一错误 envelope 响应组件。
