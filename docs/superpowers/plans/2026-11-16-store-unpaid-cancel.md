# 门店待付款订单服务端取消 Implementation Plan

**目标：** 门店 API 模式能取消本人门店待付款订单，并以订单服务回读结果更新页面。

**现状与边界：** 支付服务目前只记录支付意图和回调，未同步订单状态；本批只开放待付款取消。已付款取消、真实支付、履约及售后继续关闭。库存预占释放由订单服务调用库存服务，库存服务明确失败时订单状态不改变。本地测试不代表 Staging 或真机验收。

## 步骤

1. 先补订单服务接口审计：匿名、跨门店和非待付款状态拒绝；重复取消幂等；库存释放失败保持待付款。
2. 实现 `POST /api/v1/orders/{id}/cancel`，先校验身份和订单归属，再在事务中锁定订单、释放预占库存、更新状态和发出事件。
3. 补门店端 API 测试：请求成功后采用服务端返回状态；失败不改本地状态；仅待付款展示取消入口。
4. 运行订单服务和门店定向测试、类型检查、构建，核对推送目标后提交推送。

**本地验证：** 门店 99 项测试、订单服务 3 项普通测试和 17 项 API 审计、门店 TypeScript 检查及小程序构建通过；OpenAPI 与后端 110 个路由一致。跨服务库存释放采用本地测试替身验证，未进行真实库存服务联调；Staging 和真机未验收。

**后续风险：** 支付回调未与订单状态联动，取消与支付意图尚无跨服务互斥；库存服务释放成功后若订单服务提交失败，也缺少自动补偿。真实支付开放前需要统一处理支付/取消竞争及跨服务补偿。
