# 门店登录与订单范围接线实施计划

> 按已批准的分批方案执行；每项先写失败用例，再实现并验证。

**目标：** 门店账号在 API 模式下通过 Auth 登录并读取真实门店资料，只能创建、列出、读取所属门店订单；运营后台创建组织账号后完成 Auth 开通。

**架构：** Auth `/me` 提供已校验的 `farmId`；订单服务只信任该字段决定买家范围。后台先创建 Org 账号、再调用 Auth 开通接口，开通失败保存组织账号 ID 以供重试。门店端 API 模式使用密码登录和服务端令牌，演示验证码仅在 mock 模式使用。

**技术栈：** Spring Boot、JUnit、Taro、TypeScript、Vitest。

**依据：** `docs/superpowers/plans/2026-10-28-page-backend-remaining-plan.md` 与本轮已批准的门店真实登录方案。
