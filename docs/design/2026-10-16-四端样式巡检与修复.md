## 根因

uni-app 会把小程序不认识的 HTML 标签（`<small>/<strong>/<span>/<del>`）编译成 `<view>`，因此样式里的 `small{}`、`.cart-bar strong{}` 这类标签选择器永远匹配不到元素，价格、辅助文字的字号/颜色/字重/间距全部丢失。H5 里这些标签是真实元素，所以“浏览器正常、小程序乱”。

| 端 | 修复前失效规则 | 修复后 |
|---|---|---|
| store | 73 条（首页 62 / 结算 6 / 订单详情 5） | 0 |
| user | 35 条（首页 24 / 团长中心 11） | 0 |
| supplier | 24 条 | 0 |

## 修复清单

1. **标签选择器 → 语义 class**：`<small>`→`.meta`、`<strong>`→`.val`、`<span>`→`.chip`、`<del>`→`.strike`；声明值一字未改，观感保持不变。涉及 `apps/store`（3 个页面）、`apps/supplier`（index）、`apps/user`（index + operations）。
2. **门店端主题变量作用域**：`apps/store/src/styles/global.scss` 由 `:root {` 改为 `:root, page {`，并引入 `packages/ui/src/design-tokens.css`；`var(--color-line)` → `var(--store-line)`，解决 3 处未定义 token（`--radius-icon` ×2、`--color-line` ×1）。
3. **用户端小程序兼容**：`:has(.cart-checkout)` 改为状态类 `.cart-page--has-checkout`；27 处 `color-mix()` 改为 `rgba(var(--…-rgb), α)`，新增 `--color-on-brand-rgb`、`--color-user-brand-deep-rgb`、`--color-user-price-rgb`、`--color-user-hero-muted` 四个 token。
4. **运营后台文字裁切**（1280 实测）：
   - 订单履约「自动分配供应商」在 69px 单元格被 ellipsis 截断 → 增加 `.is-wrap` 允许换行。
   - 售后结算行内按钮被 flex 压缩（内容 63 > 容器 57）→ `.after-grid .row-actions` 由 `nowrap` 改 `wrap`。
   - 售后结算 / 操作日志搜索框 placeholder 截断（239 > 180、183 > 180）→ 两个面板的搜索框分别放宽到 290px / 250px。
5. **图标**：四端继续使用 Lucide（`UiIcon` + 小程序 PNG 兜底），未重绘任何图标；`scripts/svg-icons-to-png.mjs` 由 `@playwright/test` 改为 `playwright-core`，并支持系统 Chrome / Edge / ms-playwright Chromium 探测。
6. **防回归门禁**：新增 `pnpm audit:mp-styles`（`scripts/audit-mp-styles.mjs` + 单测），校验源码与构建产物的标签选择器、主题变量 `page` 作用域、`color-mix()`/`:has()`、`!important` 白名单。

## 真机/开发者工具回归轮（同日追加）

### 关键发现：三端小程序此前在微信侧**编译不通过**

- 现象：用真实 AppID 在微信开发者工具打开三端产物时，IDE 报 `编译 .wxss 文件错误`；
  `cli preview` 给出具体原因：`wxss 编译错误：./app.wxss(1:xxxx): unexpected token `*``。
- 根因：WXSS 不支持通配符选择器。存量有 5 处：
  1. `packages/ui/src/mobile-theme.scss` 的 prefers-reduced-motion 块（`*, *::before, *::after`）
  2. `apps/store|supplier|user/src/styles/global.scss` 的 `* { box-sizing: border-box }`
  3. `apps/supplier` 的 `.order-filter-scroll *` 与 `.product-filter-scroll *`（隐藏滚动条）
- 修复：通配符改为显式原生组件清单（`page/view/text/image/button/input/textarea/scroll-view/...`），滚动条隐藏改为作用于容器与 `button`。
- 验证：三端 `cli preview` 全部成功（store 983.1 KB / supplier 1.1 MB / user 1.1 MB），即已可上传并在手机微信中打开。

### 门禁扩展

### 本轮工具限制（未完成的自动逐页）

- `miniprogram-automator@0.13.0` 与微信开发者工具 2.02.2609231 的元素级 API 不兼容：`page.$` 报 `page node not found`，`wx.createSelectorQuery` 回调不返回，因此无法脚本化「逐页点击 + 计算样式取样」。
- 应用态 API 可用（`evaluate` / `screenshot` / `callWxMethod`），但登录与视图切换由页面 setup 状态驱动，无法从应用态调用，故逐页回归需在真机或 IDE 手动进行。
- 三端 `manifest.json` 仍为 `touristappid`；本轮真机预览临时使用本机唯一可用真实 AppID（`wx7d78d69cd175812e`）覆盖在 `dist/build/mp-weixin/project.config.json`（构建产物、不入库）。该做法会让三端共享同一存储命名空间，正式验收应为每端配置各自的小程序 AppID/测试号。
- 预览二维码（约 25 分钟有效）生成于 `artifacts/mp-regression/{store,supplier,user}-preview-qr.png`。

### 一个端一个端切换测试号（推荐流程）

微信「测试号」只能由号主本人的微信账号生成（微信公众平台 → 测试号管理，或开发者工具 AppID 下拉选「测试号」），因此按端逐个接入：

1. 拿到该端的测试号 AppID（形如 `wx` + 16 位十六进制）。
2. 写入该端 manifest：`pnpm mp:appid store wx1234567890abcdef`（支持 `--dry-run`；只改 `apps/<app>/src/manifest.json` 的 `mp-weixin.appid`）。
3. 重新构建：`pnpm build:store`。
4. 生成真机预览二维码：`cli preview --project apps/store/dist/build/mp-weixin --qr-format image --qr-output artifacts/mp-regression/store-preview-qr.png`。
5. 真机逐页验收该端，然后再切下一个端（避免三端共用同一 AppID 造成本地存储串端）。
6. 需要回退游客模式：`pnpm mp:appid store touristappid`。
